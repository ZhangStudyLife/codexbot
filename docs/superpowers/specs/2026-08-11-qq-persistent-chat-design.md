# QQ 持久 Codex 聊天模式设计

日期：2026-08-11  
目标版本：v0.3.0

## 目标

把现有一次性 QQ 命令向导扩展成可持续点击和聊天的 Codex 客户端。用户从任务列表进入一个真实 Codex 线程后，直接发送普通 QQ 文本即可继续该线程；QQ 与 Codex Desktop 始终使用同一套线程和回合。

## 已确认行为

- 只允许当前唯一绑定的 QQ 用户操作。
- 点击“进入对话”后持久保存当前线程，CodexBot 或电脑重启后继续恢复。
- 当前线程空闲时，普通文本调用 `thread/resume` 后启动新 Turn。
- 当前线程运行时，普通文本调用 `turn/steer` 追加引导。
- Turn 完成后自动把完整回复分段发送到 QQ，最后附带当前对话操作按钮。
- `/menu` 或“退出对话”退出聊天模式，但不删除或停止线程。
- 继续沿用 `approvalPolicy: never` 和 `dangerFullAccess`，不增加另一套任务存储。

## 交互结构

主菜单继续提供“新建任务”“运行中”“任务列表”等入口。任务列表和任务详情新增“进入对话”按钮。

进入后，每条机器人消息都带有当前线程的简短标题和状态。固定操作为：

- 刷新：重新读取线程并显示最新状态或输出。
- 任务详情：显示目录、状态、最近错误或输出。
- 停止：仅在线程存在活动 Turn 时调用 `turn/interrupt`。
- 切换对话：返回任务列表，等待选择另一个线程。
- 退出对话：清除当前线程并返回主菜单。

QQ Keyboard 每行最多放置两个按钮。列表仍限制为最近五个任务，避免超过 QQ 消息和按钮限制。

## 状态与路由

`ControlSession` 保留现有新建任务向导，并增加独立的当前聊天线程状态。当前线程 ID 写入现有 SQLite `settings`，不保存完整提示词或回复正文。

收到已绑定用户的消息时按以下顺序处理：

1. `/menu`、按钮指令和 `/cancel` 等控制命令优先。
2. 新建任务向导处于输入阶段时，交给向导。
3. 已进入聊天模式时，普通文本路由到当前线程。
4. 其他普通文本返回带按钮的主菜单。

发送前必须调用 `thread/read` 获取真实状态：

- `active` 或 `inProgress` 且存在 Turn ID：调用 `turn/steer`。
- 其他可恢复状态：调用现有 `continue_task`，即 `thread/resume` 后 `turn/start`。
- 线程不存在或不可读取：清除已保存线程并返回任务列表。

切换和退出只改变 QQ 控制状态，不修改 Codex 线程。

## 完整回复回传

Turn 完成通知继续以 App Server 或现有 Hook/监控结果为真实来源。对当前聊天线程：

1. 读取线程的最后一条 assistant 输出。
2. 按 QQ 单条消息安全长度切分，保持原有顺序。
3. 前面的分段发送普通文本，最后一段附加聊天操作 Keyboard。
4. 同一个 `thread_id + turn_id` 只发送一次完整回复。

非当前聊天线程保持现有简短完成或失败通知，避免多个后台任务把完整输出同时推送到 QQ。

## 错误处理

- `turn/steer` 或 `turn/start` 失败时直接返回脱敏错误，不自动重试修改请求。
- 当前 Turn 在发送前刚好结束时，重新读取一次线程；若已空闲，则作为新 Turn 提交。
- QQ 分段发送中断时保留现有 outbox 重试语义，不重复已经确认发送的分段。
- Keyboard 被 QQ 拒绝时继续退化为文字指令，但不退出聊天模式。
- 完整回复为空时发送“回合已结束，但没有可显示的回复”，并保留操作按钮。

## 最小代码改动

- `src/control_session.rs`：聊天模式路由、进入/退出/切换按钮和状态恢复。
- `src/qq_menu.rs`：聊天模式 Keyboard。
- `src/store.rs`：复用 settings 保存当前线程；仅在需要回复去重时增加最小记录。
- `src/qq_client.rs`：完整回复分段发送并在最后一段附加 Keyboard。
- `src/codex_control.rs`：只补充读取当前活动 Turn 所需的最小信息，不改变 App Server 架构。

不修改桌面 UI、账号切换、安装器和无关格式。

## 验收标准

- 从任务列表点击“进入对话”后，普通文字真实出现在同一个 Codex Desktop 线程。
- 空闲线程创建新 Turn；运行中线程使用 `turn/steer`，不会创建并行 Turn。
- 重启 daemon 后仍恢复当前线程。
- 完成后 QQ 自动收到按顺序分段的完整回复和操作按钮。
- “切换对话”和“退出对话”不会停止或删除 Codex 线程。
- 已删除或失效线程会自动退出聊天模式。
- 非绑定 QQ 用户不能读取或控制任何线程。
- 新增回归测试通过，且 `cargo fmt --all --check`、Clippy、完整测试和 Release 构建通过。
